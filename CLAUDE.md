# Contesto per Claude Code

Questo è lo scaffold pulito di **StudyBuddy v2**. Architettura già decisa; da qui si costruisce.

## Principi
- **Local-first**: default tutto su Ollama. L'API (Anthropic/OpenAI-compat) è opt-in per-task in `src/lib/config.ts`, mai una dipendenza.
- **Modulare**: la logica sta in `src/lib/*`; le route in `src/app/api/*` sono thin wrapper.
- **Provider-agnostico**: ogni chiamata LLM passa da `generate(task, opts)` / `embed(texts)` in `src/lib/providers`. Non chiamare i provider direttamente dalle feature.

## Sorgente dati: corso Coursera scaricato
L'input principale è un **corso Coursera scaricato** (cartella `corso/modulo/lezione/` con file misti):
- `.srt`/`.vtt` = **trascrizioni**, fonte primaria. Già testo pulito → niente Whisper. Parser fatto in `src/lib/rag/sources/coursera.ts` (`parseSubtitles`), chunking con timestamp via `chunkTranscript`.
- `.pdf` = slide/readings → estratto con **unpdf** (`parsePdf`, pdfjs, no native deps).
- `.html` = letture → estratto con **node-html-parser** (`parseHtml`: `<co-content>` o fallback `<body>`, tiene code/pre/tabelle, scarta script/style/chrome).
- `.mp4`/`.mkv` = saltati di default (la trascrizione copre il testo); si tiene il path per il link al video. Con `--whisper` i video **senza** .srt/.vtt vengono trascritti (fallback #8).

**Cartella-libreria**: i corsi si copiano a mano in `Courses/` (override `STUDYBUDDY_LIBRARY_DIR`, `lib/libraryDir.ts`) e si importano da `/corsi/add`. Ogni sottocartella è un elemento: **macro** se la maggioranza delle sue sottocartelle con materiale ha nomi non numerati (corsi di una specializzazione), **corso** se sono numerate (moduli `01_…`) — `classifyFolder` in `lib/ingestPlan.ts`, correggibile nell'anteprima. Gerarchia a 2 livelli macro → corsi (`resolveScope`); i **domini** (tabella `areas`, slug in `domains.areas`) sono solo organizzazione, gestiti in `/settings`.

Mappatura: corso → un **dominio**; ogni file testuale → un **documento** con `meta` { course, module, lesson, crumbs, path, fileHash }. `crumbs` è la breadcrumb completa (robusta alla profondità del path). I chunk di trascrizione portano `meta` { startSec, endSec } per citazioni cliccabili al minuto del video.
`ingestCourse(courseDir, domainId)` fa il walk + ingestione end-to-end (transcript/text pronti).

Attenzione ai **duplicati** slide-PDF vs trascrizione: stesso contenuto da due fonti → il reranker deve dedup-are.

## Note tecniche
- Stack (ott 2026): Next 16 (Turbopack di default, `src/proxy.ts` al posto di middleware, niente `next lint`), React 19.3, TypeScript 7 (tsc nativo, usato anche da `next build`), drizzle-orm 0.45, better-sqlite3 13, node-html-parser 9, @anthropic-ai/sdk 0.131.
- Turbopack traccia staticamente i path costruiti da `process.cwd()`: per file runtime fuori dal bundle (es. `.venv/bin/python` in `transcribe.ts`) usare `path.resolve(/* turbopackIgnore: true */ process.cwd(), …)`, altrimenti la build fallisce (symlink fuori root).
- `better-sqlite3`, `sqlite-vec` e `@huggingface/transformers`/`onnxruntime-node` sono nativi/non-bundlabili → in `serverExternalPackages` (next.config.ts). Le route che li usano hanno `runtime = "nodejs"`.
- Reranker cross-encoder: modello scaricato una volta in `.models/` (gitignored), caricato lazy come singleton. **GPU di default** (`device: cuda`, `dtype: fp16`, ~0.6s/20 chunk), fallback automatico su CPU (`cpuDtype: q8`, ~3.4s). Batch da 8 e `maxLength` 512 (senza troncamento il padding esplodeva: ~13s e 13GB RAM). Su GPU non usare q8: gli operatori interi non hanno kernel CUDA e tornano su CPU.
- onnxruntime-node 1.30 usa **CUDA 13** (lib di sistema; in Docker quelle dell'immagine `nvidia/cuda:13.0.2-cudnn-runtime`). Le lib CUDA 12 + cuDNN 9 nella `.venv` (`nvidia-cublas-cu12`, `nvidia-cudnn-cu12`) servono solo a ctranslate2/Whisper: `whisperEnv()` in `transcribe.ts` le mette nel `LD_LIBRARY_PATH` del **sottoprocesso Python**, mai di Node (stesso soname `libcudnn.so.9`: davanti a Node farebbero caricare a onnxruntime il cuDNN sbagliato).
- Modelli (ott 2026, scelti con un bake-off su tutor/quiz/grading): chat/quiz/grade/summarize = `gemma4:12b`, embed = `qwen3-embedding:0.6b` (multilingue: domande IT su materiale EN). Richiede Ollama ≥ 0.35.
- Embedding dim = 1024 (`EMBED_DIM` in config.ts). Se cambi modello embed, aggiorna `EMBED_DIM` e **re-indicizza su un DB nuovo**: l'ingest idempotente per `fileHash` salterebbe i file invariati lasciando i vettori del vecchio modello (risultati sbagliati senza errori).
- DB: percorso da `DB_PATH` in `.env.local` (oggi `data/studybuddy.db`, lo stesso file che usa Docker; i backup stanno accanto come `data/studybuddy.db.bak-*`; nella root restano `studybuddy-v2.db` e `studybuddy.db`, DB vecchi non più in uso). Next lo legge da solo; CLI `ingest` (tsx `--env-file-if-exists`) e `drizzle.config.ts` (`process.loadEnvFile`) sono allineati.
- `sqlite-vec` (questa build) è severo: la PK `chunk_id` di `vec0` va passata come **BigInt** (`BigInt(id)`), e le query KNN con JOIN richiedono `AND k = ?` (il `LIMIT` non basta). Vedi `rag/store.ts`.
- FTS5: tabella `chunks_fts` con **`rowid` = chunk id** (così è in sync col dense e si cancella per rowid). Tokenizer `porter unicode61 remove_diacritics 2` (EN/IT). `ensureFts()` fa backfill una-tantum se vuota; indexChunks/deleteDocumentChunks la tengono sincronizzata.
- Structured output: Ollama accetta `format` come JSON schema; il provider lo passa quando `opts.schema` è presente.
- I modelli recenti sono "reasoning": con il thinking attivo `num_predict` si esaurisce prima della risposta (output vuoto). Per questo `config.ollama.think = false` di default (opt-in per chiamata con `opts.think`). `config.ollama.numCtx` = 16k: il default Ollama (4096) tronca in silenzio il contesto RAG. Tutti i task sullo stesso modello usano questo valore per evitare ricaricamenti di Ollama fra chiamate. L’unico override necessario è l’estrazione SF6 a 32k (`extract.ts`): alternarla agli altri task può ricaricare il modello. Non aggiungere override per-task senza un budget di contesto che lo richieda. I timeout HTTP di Ollama sono configurabili con `config.ollama.headersTimeoutMs` e `bodyTimeoutMs` (30 minuti).
- Grading (Fase 2): il giudice dà `verdict` (wrong/partial/correct) dopo `required/present/missing/errors` (`required` solo da ciò che la **domanda** chiede esplicitamente); `correct` con `errors` non vuoti → partial in codice (le sole `missing` non declassano: sotto un `correct` la UI le titola «Potevi aggiungere»). Rating = `toRating(verdict, confidence?)` in `scheduler.ts` (wrong Again, partial Hard, correct Good; correct + «Sicuro» Easy, Fase 6). Il passaggio sorgente viene da `tutor/gradingSource.ts` (chunk della carta ≤ 1500 caratteri o primo risultato di `retrieve`, mai bloccante) ed è restituito alla UI (`VerdictPanel`). Un giudizio non valido (dopo un retry) **lancia** invece di restituire un voto 0, che rischedulerebbe la carta come dimenticata.
- Review log (Fase 0 del piano): `review_logs`, una riga per ripasso scritta da `reviewCard()` nella **stessa transazione** dell'update della carta (giudizio LLM fuori, prima); `ON DELETE CASCADE` sulla carta. `state_before` = stato FSRS completo prima della review, `stability`/`difficulty`/`scheduled_days` = dopo; `legacy_quality` = voto 0–5 del giudice v1, **non più scritta dalla Fase 2** (resta per i ripassi precedenti); `grader_rationale` = JSON del giudizio `{required,present,missing,errors,feedback}` (le righe precedenti sono testo semplice). Sui DB esistenti la crea `ensureHubSchema()`.
- FSRS (Fase 1): `ts-fsrs` **5.4.2 fissata** (la 6 toglie `elapsed_days`), importata solo da `tutor/scheduler.ts` (funzioni pure); parametri in `config.srs` (retention 0.9, max 365 g, fuzz, learning step di default in minuti). Colonne FSRS su `cards` (`fsrs_state`… `last_review`); quelle SM-2 non si aggiornano più. `convertCardsToFsrs()` in `ensureHubSchema()` converte le righe con `fsrs_state` NULL (tabella 1.4 del piano; lo scheduler converte anche al volo). Correzione del voto (`overrideLastReview`, `POST /api/review/override`): riparte da `state_before` e rischedula alla stessa ora, **non** con `f.rollback()` (in 5.4.2 perde il `last_review` precedente); il log originale va a `overridden = 1` e se ne aggiunge uno `grader_model = "manual"`. `reviewCard()` arrotonda `now` al secondo come `reviewed_at`: il seed del fuzz dipende dall'ora esatta.
- Fiducia (Fase 6): prima di «Valuta» (ripasso) e di «Invia» (domande aperte del quiz) si sceglie Non sicuro / Abbastanza / Sicuro (`ConfidencePicker`, tasti 1/2/3 fuori dai campi di testo, Alt+1/2/3 mentre scrivi: logica pura in `lib/client/confidence.ts`). `POST /api/review` accetta `confidence` 1–3 (facoltativa lato API, obbligatoria in UI) → `review_logs.confidence`; la correzione del voto la copia nel log manuale. Sbagliata + «Sicuro» = feedback e risposta attesa in evidenza (`VerdictPanel`). Il quiz non è persistito: lì la fiducia serve solo alla UI. Calibrazione in home: `calibration(domainId?, days=30)` in `lib/home.ts` (corretta = rating ≥ Good, log `overridden = 0`, scope in SQL per non importare il layer RAG nel layout); frase se «Sicuro» < 70% con ≥ 20 review.
- Flashcard (Fase 3): generatore dedicato `tutor/cardGen.ts` (`cards-v3`, schema `facts` → `cards` con `fact`, `type` qa|cloze, `source` [n]; il cloze è una domanda con `____`, nessuna colonna in più). Le trascrizioni passano da `rag/cleanTranscript.ts` (riempitivi, frasi di servizio, ripetizioni) solo per generare, mai per l'indice. La fonte dichiarata vale se copre ≥ 25% delle parole di fatto+risposta, altrimenti `sourceForAnswer`. `tutor/cardQuality.ts` (`checkCard`, puro, gira anche nel browser: per questo `wordShingles`/`jaccard` stanno in `lib/shingles.ts`) segnala risposta lunga (> 25 parole fuori dal codice), elenco, domanda doppia, sì/no (anche italiano: risposta «Sì/No» o «?» senza interrogativi), risposta nella domanda, rimandi al testo (`REFERS_TO_HIDDEN`, condivisa col quiz), cloze con più spazi; `markDuplicates` aggiunge «già presente». - Mappe: `tela.js` riconosce tap/doppio tap al `pointerup` perché con `setPointerCapture` sullo SVG i `dblclick` arrivano allo SVG, non alla bolla (era il motivo per cui «entrare» non funzionava). Ogni passaggio RAG nei prompt delle mappe è tagliato a 2500 caratteri (rete di sicurezza: oggi i chunk sono ≤ ~2000).
- Chunking: `chunkText` spezza i paragrafi oltre budget (righe → frasi → taglio), perché `structuredText` dell'HTML separa i blocchi con un solo `\n` (prima una pagina = un chunk, fino a 270k). `parseHtml` parsa i `<pre>` (di default node-html-parser li lascia markup letterale) e toglie i `data:` URI con una scansione lineare: immagini base64 da 15 MB mandano in stack overflow le regex di V8.
- Re-ingest e carte: `deleteDocumentChunks` sgancia `cards.source_chunk_id` (FK) in una transazione; senza, il re-ingest dei documenti con carte falliva a metà.
- Re-ingest idempotente per `fileHash`: se migliori un parser in `sources/coursera.ts` i file invariati verrebbero saltati → **bumpa `PARSER_VERSION`** per forzare il refresh.
- Organizzazione: `lib/library.ts` valida gli invarianti (macro senza genitore, corsi solo dentro macro, elimina solo macro senza dati di studio propri, domini solo esistenti). Un dominio esistente cambia nome/macro/aree solo dalla Libreria o da un piano esplicito di `/corsi/add` (`parsePlan`/`applyPlan` in `lib/ingestTree.ts`): re-importare non disfa gli spostamenti manuali.
- `ingested_files` registra ogni file elaborato (anche senza chunk): l'analisi di `/corsi/add` confronta gli hash (`fileHashOf`, include `PARSER_VERSION`) per dire nuovo/aggiornato/modificato. Un import alla volta (`activeJob`, 409).
- **Non usare `npm run db:push` sul DB reale**: le tabelle virtuali `vec_chunks`/`chunks_fts` non sono nello schema Drizzle. Migrazioni = SQL esplicito dopo un backup; le aggiunte della Libreria (`domains.areas`, `ingested_files`) le applica da sé `ensureLibrarySchema()` all'apertura del DB (`lib/db/index.ts`, idempotente). DB nuovo: si crea da solo all'apertura (`initSchema()` da `lib/db/schemaSql.ts`, generato con `npm run db:schema`: rigeneralo quando cambi `schema.ts`, un test lo controlla).
- Domini (F2): tabella `areas` (slug PK fisso, nome, simbolo, tagline, `module` dal registro `lib/modules.ts`, `position`). `domains.areas` contiene **slug**: le API dei corsi rifiutano nomi e slug inesistenti, un dominio nuovo si crea con `POST /api/areas` (anche da `AreaInput`). `ensureHubSchema()` (in `lib/db/index.ts`, dopo `ensureLibrarySchema()`) crea la tabella sui DB esistenti con lo stesso SQL di `schemaSql.ts` e converte una volta i nomi liberi in slug (`Web`/`web` = un dominio), in transazione IMMEDIATE. `LibraryError` sta in `lib/errors.ts`.
- Note (F3): tabella `notes` (`domain` slug **o** `course_id`, mai entrambi; nessuno = inbox), logica in `lib/notes.ts`. Una nota su un corso compare nei domini del corso (`listForArea`: righe visibili con lo slug + figli dei macro). La destinazione della quick capture la calcola `lib/client/captureTarget.ts` dal percorso (`/study/[id]` → corso, `/d/[slug]` e route dei moduli → dominio, altrove inbox). Non si elimina un dominio con note; eliminare un macro rimanda le sue note all'inbox. `ensureHubSchema()` crea `notes` e aggiunge `sessions.updated_at` (`ensureTable`/`ensureColumn`, ALTER in transazione IMMEDIATE). Il root layout legge il DB (`getShellData()` in `lib/home.ts`) ed è `force-dynamic`. Le route con `LibraryError` usano `handle` di `lib/http.ts`.
- Import del vault (F4): `scripts/import-vault.ts` + `lib/vaultImport/` (`read.ts` copia `vault.db`+`-wal` e legge la copia, perché aprire l'originale farebbe il checkpoint; i domini vengono da `<vault>/src/lib/domains.ts` via `import()`. `plan.ts` aggancia per slug o nome, i nuovi domini tengono lo slug del vault, esclusi e sconosciuti → inbox, note con id originali salvo collisioni. `report.ts`). Lavora su un file `*.partial-<pid>` accanto al target, ottenuto con il backup online del DB sorgente: il dry-run fa tutto e lo butta, `--apply` lo collega al target (`linkSync`, mai sovrascrivere). `settings` del vault non si porta (si stampano solo i nomi delle chiavi). Tabelle `sf6_combos`/`sf6_tips` già nello schema (F4), codice SF6 in F5.
- SF6 (F5): trascrizione con `transcribeMedia` (`lib/transcribe.ts`, asincrona via `lib/proc.ts`: mai `spawnSync` in una richiesta): backend `local` (sidecar Whisper) di default, `groq` solo con `TRANSCRIBE_BACKEND=groq` + `GROQ_API_KEY` (`lib/groq.ts`, ffmpeg a chunk da 10 min con `lib/media.ts`). Una trascrizione alla volta (`exclusive`, 409). `parseSubtitles` sta in `lib/subtitles.ts`. Estrazione: trascritto tagliato a 60k caratteri (oltre, Ollama perderebbe il system prompt), `numCtx` 32k e `maxTokens` 8192 per chiamata. `/api/sf6/upload` (multipart) è **fuori dal matcher** del proxy: Next bufferizza e tronca oltre 10 MB (`proxyClientMaxBodySize`) i corpi che passano dal proxy; la route controlla da sé host, `Origin` e Content-Type (`lib/requestGuard.ts`). yt-dlp: `.venv/bin/yt-dlp` se c'è (`venvBin`), solo URL http(s). VOD in `STUDYBUDDY_VODS_DIR` (default `data/vods`).
- Test: `npm test` (`node:test` via tsx, DB temporaneo per file con `tests/helpers/db.ts`, nessuna dipendenza da Ollama). `learning-vault/` è escluso dal typecheck e i suoi dati sono gitignored.
- **Finestra desktop**: `npm run desktop:install` mette `studybuddy.desktop` nel menu e sul desktop (percorsi assoluti: rilanciarlo se sposti il repo). `scripts/desktop/launch.sh` apre Chrome/Chromium `--app` con profilo dedicato su `/?desktop=1`; se il server non risponde fa `docker compose up -d` e alla chiusura della finestra lo ferma (un server già acceso resta acceso). «Chiudi» nella sidebar (solo con `?desktop=1`, ricordato in sessionStorage) non può usare `window.close()`: Chrome lo blocca appena c'è più di una voce di cronologia. Quindi `POST /api/desktop/quit` scrive `.desktop-quit` accanto al DB (`./data`, montato nel container) e il launcher, che lo controlla ogni secondo, termina il browser.
- **Docker**: `docker compose up -d --build` (vedi README). `network_mode: host` (Ollama sull'host), `./data` per DB e cache modelli (`STUDYBUDDY_MODELS_DIR`, `HF_HOME`), corsi montati `:ro` allo stesso percorso dell'host (`COURSES_DIR`) così `documents.source` resta valido. `/api/health?warm=1` dice se il reranker è su `cuda` (dopo un'inferenza vera). Porta/indirizzo: `STUDYBUDDY_PORT`/`STUDYBUDDY_HOST` in `.env`. La CLI funziona anche nel container: `docker compose exec studybuddy npm run ingest -- <dir> <dominio>`.

## Colori
- Prima di toccare colori, temi o UI leggi `color-boss/COLOR_BOSS.md` (sezioni 1, 9, 10).
- I colori stanno **solo** in `src/app/tokens.css`: primitive OKLCH generate con `color-boss/colorboss.py` (neutri `sand` per il light e `navy` per il dark; brand rust→ambra con tinta interpolata; `red`, `green`, `olive`) → semantici `light-dark()` (`--bg-page`, `--text-dim`, `--accent`, `--danger`…) → token di componente (menu, pannelli, `--sf6-*`). `globals.css` li espone a Tailwind con i vecchi nomi (`bg-surface`, `text-fg-dim`, `bg-accent`, `bg-scrim`…), quindi nei componenti si usano quelle utility o `var(--semantico)`. Niente hex, `rgb()` o colori Tailwind di default nei componenti (eccezione: le SVG generate in `providers/image.ts`, che sono `<img>` autonome).
- Colore nuovo = token semantico + riga `@check` in fondo a `tokens.css`. Dopo ogni modifica `npm run colors:check`: exit ≠ 0 non si consegna; i 3 warning APCA sul danger dark sono motivati nel file. Mai dichiarare un contrasto senza averlo calcolato.
- Disabilitati: `--text-subtle`/`--bg-subtle`, mai `opacity`. Stati sempre con testo o icona, non solo colore.
- Chi legge i token da JS deve risolverli su una proprietà vera (`light-dark()` resta testo nelle custom property): vedi `serialize()` in `components/mappe/tela.js`.

## Migrazione del filtro vettoriale per dominio
I nuovi indici `vec_chunks` includono `domain_id INTEGER`, filtrato direttamente nella query `MATCH` con `AND k = ?`. PK e metadato si inseriscono come `BigInt`. Un indice precedente richiede una copia migrata: `node --import tsx scripts/migrate-vec-domain.ts --from <sorgente.db> --target <nuovo.db>` verifica e scarta il backup; aggiungere `--apply` crea il nuovo file senza sovrascrivere né modificare l'originale. La migrazione conserva gli embedding, non chiama Ollama. Dopo una review della copia si può impostare `DB_PATH` sul nuovo file. Non eseguire la migrazione sui DB reali durante sviluppo/test.
